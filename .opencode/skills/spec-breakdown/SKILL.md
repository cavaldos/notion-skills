# Spec Breakdown

Decompose a specification into ordered, well-scoped tasks ready to assign.

## When to use

- Break a spec into ordered, scoped, ready-to-assign tasks. Use when asked to break down a spec, create tasks from a spec, or plan implementation work.

## Workflow

1. Read the spec and identify its functional areas.
2. Break each area into tasks small enough to estimate and assign.
3. Order tasks by dependencies and value.
4. Define acceptance criteria for each task.
5. Group tasks into milestones or slices if useful.
6. Flag ambiguity or missing requirements for clarification.

## Output format

An ordered task breakdown with acceptance criteria and dependency notes.

## Constraints

- Tasks must map to the spec - do not invent scope.
- Keep each task independently meaningful and testable.
