# Release Notes Draft

Convert a technical change list into clear, user-friendly release notes.

## When to use

- Turn a list of changes into clear, user-facing release notes. Use when asked to write release notes, changelog entries, or update notes from a change list.

## Workflow

1. Review the list of changes and identify user impact for each.
2. Group changes into categories: New, Improved, Fixed, Removed, Known issues.
3. Write each item in user terms: what changed and why it matters.
4. Distinguish user-facing changes from internal/technical ones.
5. Add version number and date; keep tone consistent.

## Output format

Clean release notes grouped by category, written for users.

## Constraints

- Do not fabricate changes - only use the provided list.
- Keep items short and concrete; no internal jargon for users.
